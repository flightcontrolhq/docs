SvelteKit uses an adapter for its deployment target. Choose `adapter-static` for a prerendered site on S3 and CloudFront, or `adapter-node` for a Node server on ECS Fargate behind an Application Load Balancer.

<Prompt description="Set up this SvelteKit app for Ravion static or server hosting." icon="sparkles" actions={["copy", "cursor"]}>
  Use https://www.ravion.com/docs/deploy/sveltekit as the source of truth and:
  1. Confirm this repository contains SvelteKit and locate the app root in a monorepo.
  2. Inspect `package.json`, `svelte.config.*`, and adapter settings to determine the real build command, static versus Node mode, output, start command, and port.
  3. Generate `ravion.yaml` with the matching `rvn-aws-static` or ECS module set and real AWS, branch, repository, and output values. Bind Node mode to `0.0.0.0`.
  4. Run `ravion project config apply <given-id> --file ravion.yaml --dry-run`, show the plan, and apply only after confirmation.
  5. Leave TODOs instead of guessing missing AWS account IDs, repository slugs, project IDs, adapter settings, or database credentials.
</Prompt>

## Static adapter

Install `@sveltejs/adapter-static`, prerender the routes you need, and keep the adapter output in `build`.

```yaml ravion.yaml
project:
  givenId: sveltekit-static
  name: SvelteKit static site
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: static-site
        name: SvelteKit static site
        type: rvn-aws-static
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: sveltekit-static-production
          routing: filesystem
          default_version: main
          build_source: railpack
          source_repo: my-org/my-sveltekit-site
          output_directory: build
          railpack_build_cmd: npm run build
          build_infrastructure_type: ec2
          build_instance_size: c7a.4xlarge
```

## Node adapter

Install `@sveltejs/adapter-node`. `npm run build` writes a standalone server to `build`, and `node build` starts it on port `3000`.

```yaml ravion.yaml
project:
  givenId: sveltekit-app
  name: SvelteKit app
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: network
        name: Network
        type: rvn-aws-network
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: sveltekit-production
      - givenId: cluster
        name: ECS cluster
        type: rvn-ecs-cluster
        version: 1.0.0
        input:
          network:
            moduleGivenIdRef: network
          name: sveltekit-production
      - givenId: web
        name: SvelteKit web service
        type: rvn-ecs-web
        version: 1.0.0
        input:
          cluster:
            moduleGivenIdRef: cluster
          name: sveltekit-production-web
          build_source: railpack
          source_repo: my-org/my-sveltekit-app
          railpack_build_cmd: npm run build
          railpack_start_cmd: node build
          build_infrastructure_type: ec2
          build_instance_size: c7a.4xlarge
          deployment_strategy: rolling
          container_port: 3000
          health_check_path: /
          health_check_matcher: 200-399
          capacity_provider: fargate
          fargate_size:
            vcpu: 0.5
            memory_gb: 1
```

The Node adapter reads `PORT` and `HOST` environment variables. Bind to `0.0.0.0` in ECS.
