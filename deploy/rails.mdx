Deploy Rails with its bundled Puma server on ECS Fargate behind an Application Load Balancer. Rails binds to localhost by default, so the production command must bind to `0.0.0.0`.

<Prompt description="Set up this Rails app for Ravion ECS hosting." icon="sparkles" actions={["copy", "cursor"]}>
  Use https://www.ravion.com/docs/deploy/rails as the source of truth and:
  1. Confirm this repository contains Rails and locate the app root in a monorepo.
  2. Inspect `Gemfile`, Rails config, Docker files, credentials, assets, and scripts to detect the real Puma start command, port, health path, and migration or asset steps; bind to `0.0.0.0`.
  3. Generate `ravion.yaml` with `rvn-aws-network` + `rvn-ecs-cluster` + `rvn-ecs-web` + `rvn-rds`, using Secrets Manager for `DATABASE_URL` and `RAILS_MASTER_KEY` rather than inventing RDS references.
  4. Run `ravion project config apply <given-id> --file ravion.yaml --dry-run`, show the plan, and apply only after confirmation.
  5. Leave TODOs instead of guessing AWS account IDs, repository slugs, project IDs, or database credentials.
</Prompt>

## Configure the deployment

```dockerfile
FROM ruby:3.3-slim
WORKDIR /app
COPY Gemfile Gemfile.lock ./
RUN bundle install
COPY . .
CMD ["bin/rails", "server", "-e", "production", "-b", "0.0.0.0", "-p", "3000"]
```

```yaml ravion.yaml
project:
  givenId: rails-app
  name: Rails app
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: network
        name: Network
        type: rvn-aws-network
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: rails-production
      - givenId: cluster
        name: ECS cluster
        type: rvn-ecs-cluster
        version: 1.0.0
        input:
          network:
            moduleGivenIdRef: network
          name: rails-production
      - givenId: database
        name: PostgreSQL database
        type: rvn-rds
        version: 1.0.0
        input:
          network:
            moduleGivenIdRef: network
          name: rails-production-db
          restore_mode: none
          db_name: rails
          username: rails
          engine: postgres
          engine_major_version: "15"
          instance_class: db.t4g.micro
          allocated_storage: 20
      - givenId: web
        name: Rails web service
        type: rvn-ecs-web
        version: 1.0.0
        input:
          cluster:
            moduleGivenIdRef: cluster
          name: rails-production-web
          build_source: dockerfile
          source_repo: my-org/my-rails-app
          dockerfile: Dockerfile
          container_port: 3000
          health_check_path: /
          health_check_matcher: 200-399
          capacity_provider: fargate
          fargate_size:
            vcpu: 0.5
            memory_gb: 1
```

Set `RAILS_MASTER_KEY`, `SECRET_KEY_BASE`, and `DATABASE_URL` as runtime secrets. Populate the database secret from the RDS outputs before applying the service.

## Apply and connect your domain

```bash
ravion project create --given-id rails-app --name "Rails app"
ravion project config apply rails-app --file ravion.yaml --dry-run
ravion project config apply rails-app --file ravion.yaml
```

Follow [custom domains](/guides/custom-domains) to connect your domain to the Application Load Balancer.
