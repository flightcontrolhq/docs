Deploy Gatsby's generated `public` directory to S3 and serve it through CloudFront in your AWS account.

<Prompt description="Set up this Gatsby app for Ravion static hosting." icon="sparkles" actions={["copy", "cursor"]}>
  Use https://www.ravion.com/docs/deploy/gatsby as the source of truth and:
  1. Confirm this repository contains Gatsby and locate the app root in a monorepo.
  2. Inspect `package.json` and `gatsby-config.*` to detect the real build command and generated `public` directory, including any path prefix.
  3. Generate `ravion.yaml` with `rvn-aws-static`, filesystem routing, and the repository's real AWS account, region, branch, and slug.
  4. Run `ravion project config apply <given-id> --file ravion.yaml --dry-run`, show the plan, and apply only after confirmation.
  5. Leave TODOs instead of guessing missing AWS account IDs, repository slugs, project IDs, or output paths.
</Prompt>

## Configure the deployment

```yaml ravion.yaml
project:
  givenId: gatsby-site
  name: Gatsby site
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: static-site
        name: Gatsby site
        type: rvn-aws-static
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: gatsby-site-production
          routing: filesystem
          build_source: railpack
          source_repo: my-org/my-gatsby-site
          output_directory: public
          railpack_build_cmd: npm run build
```

Gatsby runs `npm run build` and writes the production files to `public`. Add public build-time values to `build_environment_variables`.

## Apply and connect your domain

```bash
ravion project create --given-id gatsby-site --name "Gatsby site"
ravion project config apply gatsby-site --file ravion.yaml --dry-run
ravion project config apply gatsby-site --file ravion.yaml
```

Complete [custom domains](/guides/custom-domains) to configure DNS and TLS.
