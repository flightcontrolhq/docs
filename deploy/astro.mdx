Deploy your Astro static build to an S3 bucket behind CloudFront. The bucket and distribution stay in your AWS account, and Ravion versions each deployment.

<Prompt description="Set up this Astro app for Ravion static or SSR hosting." icon="sparkles" actions={["copy", "cursor"]}>
  Use https://www.ravion.com/docs/deploy/astro as the source of truth and:
  1. Confirm this repository contains the Astro app and locate its root in any monorepo.
  2. Inspect `package.json` and `astro.config.*` to detect the real build command, adapter, output mode, server entry, and port. Preserve `PUBLIC_` for browser-visible variables.
  3. Generate `ravion.yaml` using the static `rvn-aws-static` modules or SSR `rvn-aws-network` + `rvn-ecs-cluster` + `rvn-ecs-web` modules, with real repo and AWS values substituted. Bind SSR to `0.0.0.0`.
  4. Run `ravion project config apply <given-id> --file ravion.yaml --dry-run`, show the plan, and apply only after confirmation.
  5. Leave TODOs instead of guessing missing AWS account IDs, repository slugs, database credentials, or adapter output.
</Prompt>

## Configure the deployment

For a static Astro site, `astro build` writes to `dist`. Set `routing` to `filesystem` so generated paths resolve to their files.

```yaml ravion.yaml
project:
  givenId: astro-site
  name: Astro site
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: static-site
        name: Astro site
        type: rvn-aws-static
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: astro-site-production
          routing: filesystem
          default_version: main
          build_source: railpack
          source_repo: my-org/my-astro-site
          output_directory: dist
          railpack_build_cmd: npm run build
          build_infrastructure_type: ec2
          build_instance_size: c7a.4xlarge
```

## Apply the config

<Steps>
  <Step title="Create the project">
    ```bash
    ravion project create --given-id astro-site --name "Astro site"
    ```
  </Step>
  <Step title="Preview and apply">
    ```bash
    ravion project config apply astro-site --file ravion.yaml --dry-run
    ravion project config apply astro-site --file ravion.yaml
    ```
  </Step>
</Steps>

Astro variables prefixed with `PUBLIC_` are exposed to browser code. Add them to `build_environment_variables` when they are required at build time. Keep server-only values out of a static build.

## Custom domain

Use the CloudFront distribution hostname from the module outputs, then follow [custom domains](/guides/custom-domains) to add an ACM certificate and DNS record.

## Astro SSR on ECS

For on-demand rendering, install `@astrojs/node`, set `output: "server"`, and configure standalone mode. Astro writes the server entry to `dist/server/entry.mjs`; run it with Node on port `4321`.

```yaml ravion.yaml
project:
  givenId: astro-ssr
  name: Astro SSR app
environments:
  - givenId: production
    name: Production
    moduleInstances:
      - givenId: network
        name: Network
        type: rvn-aws-network
        version: 1.0.0
        input:
          aws_account_id: ravion-prod
          aws_region: us-east-1
          name: astro-ssr-production
      - givenId: cluster
        name: ECS cluster
        type: rvn-ecs-cluster
        version: 1.0.0
        input:
          network:
            moduleGivenIdRef: network
          name: astro-ssr-production
      - givenId: web
        name: Astro SSR web service
        type: rvn-ecs-web
        version: 1.0.0
        input:
          cluster:
            moduleGivenIdRef: cluster
          name: astro-ssr-production-web
          build_source: railpack
          source_repo: my-org/my-astro-app
          railpack_build_cmd: npm run build
          railpack_start_cmd: node ./dist/server/entry.mjs
          build_infrastructure_type: ec2
          build_instance_size: c7a.4xlarge
          deployment_strategy: rolling
          container_port: 4321
          health_check_path: /
          health_check_matcher: 200-399
          capacity_provider: fargate
          fargate_size:
            vcpu: 0.5
            memory_gb: 1
```

Set `HOST=0.0.0.0` and `PORT=4321` in the runtime environment. Use the ECS service's Application Load Balancer hostname for your custom domain.
