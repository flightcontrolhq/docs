Build application artifacts — container images, Lambda functions, and static assets — from your source. Ravion puts build configuration next to the module that consumes the artifact, then passes a pinned result to deployment.

## How it works

Module builds run through pipelines on temporary EC2 instances in your AWS account. A build produces a pinned artifact reference that a later deploy can consume.

<Steps>
  <Step title="Configure the module">
    Set the source repository and builder in the module inputs. ECS modules can build with Railpack or a Dockerfile, or pull an existing registry image.
  </Step>
  <Step title="Add a build step">
    Point a `build` step at the module instance and pass values such as a branch or commit.
  </Step>
  <Step title="Pass the artifact forward">
    Use the build output, such as `image_digest`, `s3_directory`, or `s3_key`, as the input to a deploy step.
  </Step>
</Steps>

## Build a module in a pipeline

This pipeline builds the module for the selected variant and passes the commit through to the module:

```yaml pipeline.yaml
inputs:
  - id: branch
    type: string
    default: main
  - id: commit
    type: string
    required: false
variants:
  - id: production
    name: Production
steps:
  - id: build_web_app
    name: Build web-app
    type: build
    module_instance: << pipeline.variant.id >>.web-app
    input:
      branch: << pipeline.input.branch >>
      ref: << pipeline.input.commit >>
  - id: deploy_web_app
    name: Deploy web-app
    type: deploy
    module_instance: << pipeline.variant.id >>.web-app
    input:
      image_ref: << steps.build_web_app.output.image_digest >>
```

The `build` step outputs `build_ref` and type-specific values such as `image_uri`, `image_digest`, `s3_directory`, and `s3_key`. The deploy consumes the exact artifact produced by the build.

## Choose your builder and destination

| Artifact | Documented options |
| --- | --- |
| ECS container image | Railpack, Dockerfile, or pull from an image registry |
| Static site | Railpack or Dockerfile build to S3 |
| Lambda zip package | Package build to S3, or pull from S3 |
| Lambda container image | Railpack or Dockerfile build to ECR, or pull from an ECR image registry |

Railpack provides automatic framework detection. For standalone pipeline CI steps, use `railpack`; the `nixpacks` builder is deprecated.

If you need to control the cache source yourself, use a standalone `build:image` step:

```yaml
- id: build_image
  type: build:image
  source:
    type: git
    repo: https://github.com/my-org/my-repo
    branch: main
  builder:
    type: dockerfile
    dockerfile: Dockerfile
    cache_from:
      tag: release
  destinations:
    - id: ecr
      type: ecr
      repository_arn: arn:aws:ecr:us-east-1:123456789012:repository/my-app
  infrastructure:
    type: ec2
    instance_size: medium
```

Container module builds reuse Docker layers from the destination ECR repository. Static and Lambda builds do not use registry layer cache.

## Build in Ravion or outside it

You can build with a Ravion pipeline, or build in GitHub Actions or another CI system and hand Ravion the finished artifact:

```bash
ravion deploy create --module-instance-id <mi-id> \
  --description "Release $GITHUB_SHA" \
  --inputs '{"image_ref":"<tag-or-digest>"}'
```

There is no standalone `ravion build` command. To inspect a pipeline build, use `ravion pipeline run get <pipeline-run-id>` and `ravion logs pipeline-step <step-execution-id>`.
